# 脑机接口外设综述写作与生产规范

> 本文件是每次讨论提纲、提取材料、生成初稿和修改正文前的强制检查文件。
> 执行前同时读取《项目进度.md》，确认当前所处的生产阶段。

## 1. 项目目标与篇幅

- 侵入式脑机接口外设：3500—4500 字。
- 非侵入式脑机接口外设：3500—4500 字。
- 两部分合计：7000—9000 字。
- 总引“脑机接口外设的定义、作用与发展概况”待两部分主体完成后撰写。
- 核心任务：说明外设解决什么需求、有哪些主要方案、怎样与神经接口协同、已经实现什么能力，以及相应证据与成熟度。
- 语言采用平实的科学语言，专业程度介于学术论文和大众科普之间。事实和准确引用承担主体，评述保持简短、明确。

## 2. 生产阶段必须逐级通过

| 阶段 | 核心任务 | 进入下一阶段的条件 |
|---|---|---|
| A. 功能分类 | 确定功能需求及子类 | 分类轴统一，并通过 MECE 检查 |
| B. 原始证据库 | 收集原始研究、官方资料和关键数字 | 关键事实有准确来源，数字完成复核 |
| C. 功能级提纲 | 明确本节回答的问题、四段结构和待验证的工作结论 | 作者确认功能目标、协同逻辑和暂定判断 |
| D. 段落级提纲 | 确定中心句、案例详略和字数 | 必写、略写、舍弃案例已经区分 |
| E. 初稿 | 沿确认提纲成文 | 结构比例、外设落点和引用完整 |
| F. 作者修改 | 作者调整措辞、观点与权重 | 作者确认内容范围和判断 |
| G. 引用复核 | 逐句核来源、数字和证据边界 | 引文真实、匹配、就近，数字无歧义 |
| H. 定稿 | 统一语言、篇幅和跨节衔接 | 本功能类别单独定稿 |

每次开始工作前，先在《项目进度.md》中确认当前阶段。前置阶段存在未决问题时，当前轮只解决该问题。

## 3. 功能类别的固定正文结构

每个功能类别统一采用四部分：

1. **功能目标，约 10%**
   - 明确要恢复或建立什么能力，以及所针对的具体功能障碍。
   - 只回答为什么需要这类外设、最终要实现什么。

2. **协同方式与基本原理，约 15%**
   - 说明核心读写设备输出或接收什么信息，外设怎样转换、执行、呈现或反馈。
   - 只回答系统怎样工作，减少功能价值的重复陈述。

> **功能目标与协同原理同样需要引文**（2026-08-19 定）。需求判断引用用户调查、系统综述或监管文件，原理与链路描述引用领域综述或指南。这两部分不是作者的推断，必须与案例部分一样可回溯到权威来源；找不到来源时缩小表述范围，不写成通行结论。

3. **代表性案例与实现能力，约 65%**
   - 说明具体系统采用什么外设、怎样协同、在什么参与者和场景中实现什么能力。
   - 相近案例合并比较，突出路线、功能、场景和成熟度差异。

4. **成熟度与证据边界，约 10%**
   - 交代样本规模、家庭使用、监管状态、可推广程度和主要限制。
   - 回看全部案例后，检验、修改或否定 C 阶段的工作结论，再给出有限、可由证据支持的最终结论。

## 4. 外设章节的统一落点

> **落点在外设，评价单位是完整脑机接口系统。**

正文主线是外设怎样嵌入脑机接口闭环，并把神经能力转化为现实功能。每项外设信息必须说明至少一项：

- 它接收或产生什么神经接口信息。
- 它扩展了什么完整系统功能。
- 它的哪些参数影响系统性能、安全性或可用性。
- 它造成了什么实际限制。

保留完整系统的速度、准确率和使用效果，用于证明外设形成了可用功能。只在指标能够解释外设价值时展开。避免重复硬件章节已经详细介绍的电极、芯片和集成系统，也减少临床应用章节将重点讨论的疗效叙述。

### 4.1 小节标题按外设命名

功能需求决定分节，标题报外设。读者看到目录即可判断本章讨论对象是外设，而非硬件、软件或临床疗效。已确认的六个标题：

| 功能类别（组织依据，不进标题） | 正文标题 |
|---|---|
| 侵入式·语言与通信输出 | 文字与语音终端：把神经活动转为语言 |
| 侵入式·物理执行与运动恢复 | 机械臂与电刺激装置：把运动意图转为动作 |
| 侵入式·人工感觉输入与反馈 | 传感器与皮层刺激器：把环境信息转为感觉 |
| 非侵入式·信息选择与数字访问 | 刺激屏与拼写终端：把选择指令转为数字操作 |
| 非侵入式·运动辅助与康复训练 | 康复机器人与电刺激设备：把运动意图转为训练反馈 |
| 非侵入式·脑状态反馈与自适应交互 | 脑电头带与自适应界面：把脑状态转为环境调整 |

标题采用「设备名：功能短语」两段式（2026-08-19 定）。设备部分取两项、每项四到六字，用具体设备类别而非“效应器”这类统称；功能部分统一写成“把 X 转为 Y”，用平实的科学语言，不用口语化表达。这样读者只看目录即可判断本节讨论哪类外设、对应哪项功能。

### 4.2 段落按外设排，不按论文排

每个小节内部按外设承担的角色分段，论文退为段内例证。

- 段落首句是关于外设的判断，主语是设备或设备层，不是研究团队。
- **句内主语同样适用本条（2026-08-21 补，此前只管首句，导致精修阶段逐句返工）**：段落里的每一个陈述句，主语都应是外设或外设的参数，团队降为定语或状语。
  - 写作：`某某等的〈外设〉+ 外设自身的动作`（“Metzger 等的代码词拼写界面接收字母序列”）。
  - 或：`在某某等的对照测试中，〈外设〉……`——**对照实验类研究保留团队名于状语位**，因为承重信息是实验设计，去掉读者无从核对。
  - 纯参数类、无设计争议的研究，团队名可省，由引文序号承担出处。
  - 反例（本项目实际出现过，一律改写）：“Willett 等的手写系统产生逐字符流”“Cajigas 等让 1 名 C5 参与者用上肢运动想象启动跑台”“Downey 等把机械臂与深度摄像机结合”。
- 一段可以引用多篇论文；同一篇论文承担两种外设角色时，可在两段中各出现一次，各写各的角色。
- 判据：遮住全部引文编号后重读该段。剩下的内容若是“某某团队做了什么”，即为按论文排，需要改写；剩下的内容若是“这类外设承担什么、什么参数限制了它”，即为按外设排。
- 论文的发表顺序只在叙述外设本身的演进时才作为段落顺序。
- **小节的开头段必须给出“这类外设承担哪几件事”的纲**，与后续加粗小标题一一对应。缺这句时，开头会直接跳进某个具体数字，读者不知道下面要讲什么（信息选择一节曾以一个系统综述数字开篇，该数字实为成熟度证据，已移至节末）。

### 4.3 小节内部的外设分组

每个功能类别按下列三组之一组织，组名进入正文的加粗小标题，同样使用具体设备名：

1. **信息输出类**（语言与通信、信息选择）：呈现终端 → 输入映射层 → 承载设备与使用环境。映射层指屏幕键盘、扫描界面、鼠标键盘映射和操作系统开关控制，它决定同样的神经带宽能撬动多大的操作范围，必须单独成段。
2. **动作输出类**（运动执行与康复）：执行器 → 环境感知与共享自主 → 支撑、安全与失效处理。
3. **感觉输入类**：传感器 → 编码与刺激控制 → 安全监测与感觉稳定性。
4. **脑状态反馈类**（非侵入式的脑状态反馈与自适应交互）：状态估计设备 → 反馈或环境调整终端 → 效果归属与证据边界。

### 4.4 两个部分各自的横向评价轴

- **侵入式**：系统开启时的即时功能代偿，与系统关闭后仍可保留的改善。两者分别记录。
- **非侵入式**：使用负担（佩戴、导电膏处理、清理、每次校准所需时间与辅助人员）；性能归属（完整系统的表现有多少由外设、共享控制或通用软件承担，多少由脑信号承担）。

横向轴在每节的成熟度段必须被回检一次。

第三组在各类中都对应本章独有的内容：安装与佩戴负担、误触发与急停、疲劳与耐受、故障恢复。硬件、软件和临床应用章不覆盖这些，应保证每个功能类别至少写到一处。

## 5. 案例分为重点案例与辅助案例

### 5.1 所有案例必须有明确主语

具体案例第一次出现时，至少明确作者、团队、系统、机构或产品中的一项。优先级如下：

1. 具有稳定名称的系统或技术平台，例如 BrainGate、UCSF BRAVO、Synchron Stentrode。
2. 经权威来源核实的研究团队或机构。
3. 具有明确商业主体的企业与产品。
4. 缺少稳定系统名称时，使用论文第一作者“某某等”。

每个具体案例至少回答：

> 谁做的 → 使用什么系统或外设 → 在谁和什么场景中完成 → 实现了什么结果

研究系统、临床试验平台和商业产品必须准确区分。机构与团队归属需要权威来源支持。同一参与者或同一系统的连续论文应说明继承关系，避免被理解成多个彼此独立的人体案例。

### 5.2 重点案例的写法

重点案例按照以下顺序展开：

> 用户功能需求 → 外设与核心读写设备的协同方式 → 影响系统的关键外设参数 → 完整系统效果 → 成熟度与限制

关键外设参数可以包括重量、自由度、响应延迟、传感器精度、设置时间、连续使用时间、设备兼容性和辅助人员依赖。论文未报告时写“未报告”，不自行推算。

### 5.3 辅助案例的写法

- 可将功能相近的多项研究合并在一至两句中。
- 每项研究仍需明确主体、系统或技术名称、核心能力，并将引用放在对应分句附近。
- 辅助案例用于证明路线具有连续证据、扩大语言或设备覆盖、补充历史演进，不重复重点案例的完整结构。

已确认的辅助案例范式：

> 多项研究已经证明文字终端能够承接不同粒度的神经输出：Willett 等开发的 BrainGate 尝试手写系统实现了每分钟 90 字符的在线输入[5]；Metzger 等开发的 UCSF BRAVO 拼写系统通过 26 个代码词完成字母和句子输出[12]；Qian 等开发的普通话系统则将 394 个普通话音节接入中文显示和语音终端[8]。

已确认的重点案例范式：

> Card 等报告的长期家庭系统将神经转写结果映射为键盘输入，将神经光标映射为鼠标输入，再连接个人计算机、显示器和视频通信终端。[1] 一名肌萎缩侧索硬化参与者在 19 个月内累计使用超过 3800 小时，系统启动后最长可连续运行 19 小时；受训照护者每日设置外部硬件约需 20 分钟，说明该系统已能支持长期数字交流，同时仍依赖照护者、研究级计算设备和经皮连接。

### 5.4 综述覆盖度与正文密度

- 详细展开少量最能说明外设价值的案例。
- 以并列引用保留更多权威原始研究，体现综述覆盖度。
- 案例占主体，同时保持功能目标、统一协同原理和成熟度判断的完整比例。
- 字数紧张时优先压缩重复数字和场景描述，保留案例主体、外设协同、关键参数和证据边界。

## 6. 证据与引用规则

- 优先使用同行评议原始研究、权威综述、监管文件和项目官方资料。
- 每个关键数字必须有直接出处，医疗相关数字逐项核对。
- 引用必须真实存在，并直接支持相邻陈述。
- 字符速度、单词速度、词错误率、字符错误率、听者可理解率等指标保持原论文口径。
- 不同参与者、任务、词表和在线或离线条件下的数字不得直接合并比较。
- 部件参数与完整系统指标分开表述。
- 来源未报告的信息明确写“未报告”。
- 企业声明与同行评议证据分开记录。
- 提纲讨论和案例取舍阶段，每项事实与案例均对应原始证据库卡片编号。初稿及后续正文统一使用顺序编码制引用，如 `[24,25]` 或 `[27–30]`；正文草稿中不保留 E01、N01、P01 等证据卡编号或相关注释。
- 原始证据库未收录的信息统一标记为“待核”，完成权威来源核验前不得写入正文。

### 6.1 群体级证据的写法（非侵入式部分为主）

- 组内改善与组间优效分开表述；组间差异未达显著时必须写出。
- 荟萃分析的置信区间与预测区间分开写；亚组结果与总体结果分开写。
- 单臂研究只写组内变化，不写成优效。
- 商业产品分三层写：器械本体的监管许可、系统整体的监管许可、该产品的人体效能证据；三者常不同步。
- 群体级证据的段落主语仍是外设，研究规模作为证据强度的限定语出现，例如“反馈外设中功能性电刺激的效应量最高（10 项随机对照试验、290 人）”。

## 7. 写作边界与语言

- 采用肯定、直接、平实的科学语言。
- 首次出现的术语、缩写和指标给出一句简短解释。
- 禁用“不是……而是……”及其变体。
- 少用比喻、拟人、交易和债务类修辞。
- 每段围绕一个中心判断推进，减少案例清单感。
- 事实与推断明确区分；证据不足时缩小结论范围。

**7.1 英文术语不得逐词直译（2026-08-21 立，精修阶段集中暴露）**

英文术语进中文前先查该术语在中文文献里的通行译法，查不到就按它的实际含义意译，不要按词序硬转。本项目已出现的错误见核查日志第 10 节第 27—30 条（Action Research Arm Test、realistic simulator、professional controllers、responsive media、Mobile Arm Support）。判据：**把译名单独念给不懂英文原词的人听，他理解的意思是否与原义一致。**“动作研究臂测试”会被理解成有个东西叫“研究臂”，即为不合格。

**7.2 并列项必须处在同一维度**

列举场景、人群、类别时先检查是否 MECE。已出现的错误：“已进入康复中心、工作场景与消费市场”——机构类型、使用场合、销售渠道三个维度混排，应统一为使用场所（康复中心、工作场所、家庭）或使用者身份（患者、在职操作人员、一般消费者）。

**7.3 一句话只装一件事**

参数密集处按“空间布局 / 刺激波形 / 控制逻辑”分句，每个数字带上它修饰的对象。已出现的错误：把电极数、电极间距、脉率、脉宽、幅度、更新周期串成一句（Bouton 袖套）；把速率指标与准确率指标用顿号并列（Beauchamp 形状辨别）。

**7.4 压缩说法必须保留中心词**

省略中心词造成的病句在精修阶段占比很高：“2 人实验室研究”（缺“样本量为”）、“40 目标频率与相位联合编码的界面”（缺展开）、“1 秒时间窗、稳态视觉诱发电位条件下的离线准确率”（三个限定并排堆叠）。**判据：这个短语能否被不熟悉该研究的读者一次读懂。**

## 8. 每次初稿前后的检查

### 成文前

- [ ] 已读取本文件和《项目进度.md》。
- [ ] 已确认当前生产阶段及本轮唯一目标。
- [ ] 已读取对应功能的原始证据库与数值核查日志。
- [ ] 段落级提纲中的每项事实与案例均已对应原始证据卡编号。
- [ ] 已确认子类、段落顺序、中心句和字数分配。
- [ ] 已确定重点案例、辅助案例和暂不采用的案例。
- [ ] 已提出本节待案例检验的工作结论，并明确可能推翻它的证据。

### 成文后

- [ ] 功能目标、协同原理、案例和成熟度大致符合 10%—15%—65%—10%。
- [ ] 每个具体案例都有明确主语。
- [ ] 每个重点案例符合统一案例结构。
- [ ] 每个关键数字就近引用，且与来源口径一致。
- [ ] 外设是叙述落点，完整系统是评价单位。
- [ ] 小节标题为具体设备名；加粗小标题按 4.3 的三组结构划分。
- [ ] 遮住引文编号后重读，每段剩下的是外设判断而不是团队清单。
