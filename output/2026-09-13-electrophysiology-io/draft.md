## 已定稿

### 为了回答实验问题，先明确需要知道什么

搭建一套实验记录系统，首先要问：为了回答实验问题，我们需要知道什么？

以“小鼠受到光刺激后，神经活动和行为怎样变化”为例，我们需要收集四类信息：

| 信息 | 需要知道的内容 |
| --- | --- |
| 神经活动 | 电极记录到的电信号怎样随时间变化 |
| 行为 | 小鼠在视频中表现出怎样的运动或动作 |
| 刺激情况 | 光实际何时亮起、持续多久；与实验问题相关的刺激参数也需记录 |
| 时间对应关系 | 电信号、行为与刺激记录怎样对应到同一段实验时间上 |

这里需要区分两条信息：“发出了开灯指令”和“光实际亮了”。前者说明控制端做了什么；后者需要来自实际发光的测量或验证。仅凭指令记录，对实际发光时刻的判断仍需要验证依据。

先明确需要收集的信息，再判断需要哪些传感器和控制设备，以及哪些信息需要在设备之间传递。

### 从信息需求逐步落实到工程实现

已确认的学习顺序：

研究问题或功能目标 → 需要知道、收集什么 → 需要测量、判断、控制什么 → 设备之间需要传递什么 → 所需设备与性能 → 接口选择与工程实现 → 接线、验证与排障。

不同需求会影响工程方案；同一个需求也可能有多种实现方式。选择依据包括准确性、响应时间、可靠性、使用环境和成本。

### 时间对应与控制依赖分别说明设备关系

时间对齐解决各项记录的时间如何对应。设备可以共享时钟，也可以使用各自的时钟，再通过同步信息测量并校正时间差；具体精度需要验证。

触发机制规定哪个信号使哪个动作开始。例如，光刺激可以按预设时间执行，也可以由检测到的电信号或行为决定。

Analog（模拟）接口通常以连续变化的电压表示信息；Digital（数字）接口按照规定将电压状态或变化解释为离散信息。In（输入）和 Out（输出）表示信号相对于所在设备的方向。这些接口可以传递测量值、事件或控制指令，以及同步信息。

| 1. 实验目的决定信息与性能需求 | 为了回答问题，需要知道什么？每项信息要达到什么要求，未达到会使哪条结论出错？ | 以闭环主例（检测到特定神经活动即给光刺激，同时记录神经信号与行为视频）形成需求与验收清单。需求用现象的量书写（事件最短持续、最小幅值、光须在事件后多长时间内亮起、记录总时长），换算为设备参数留给第 4、7 期。 |
| 2. 设备职责决定信息通路 | 谁测量、谁判断、谁执行、谁保存，彼此传什么？ | 画出系统功能与信息方向图；理解模拟、数字、输入、输出；区分离散数字事件端口与传送数字数据的通信接口。能判断何时需要四类接口，何时通过通信或设备内部连接实现。 |
| 3. 电气兼容决定连接方式 | 发送端产生什么，接收端允许什么，两端怎样建立电气连接？ | 理解电压参考、电流与回路、输入输出阻抗（端口电压与电流之间的关系）、负载（输出端所连接的电路）、接地、差分测量（测量两个输入端之间的电压差）、屏蔽与隔离；能核对引脚、允许范围与连接条件。区分信号参考地、屏蔽及保护接地的作用。 |
| 4. 模拟输入把测量信号转换为数据 | 一个物理量怎样成为可解释的记录数值？ | 理解传感、信号调理（调整信号以适合采集）、模数转换（将模拟信号转换为数字数值）、采样、滤波及单位换算；区分电极输入和通用模拟输入。能判断输入范围、带宽（可记录的频率范围）和有效测量精度，解释削顶、噪声与混叠（不同频率在采样后变得无法区分）。 |
| 5. 模拟输出把设定值转换为控制信号 | 软件中的数值怎样变成电压，并最终影响外部设备？ | 理解数模转换（将数字数值转换为模拟信号）、输出范围、波形更新时间、驱动能力与独立驱动器；区分控制信号与实际刺激或动作。能判断何时需要模拟输出，并验证设定值与实际结果的关系。 |
| 6. 数字输入输出使状态与事件可识别 | 一个状态、脉冲或事件编号怎样被正确接收？ | 理解高低电平判定、有效极性（哪个状态或变化代表有效）、边沿（电平跳变）、脉冲持续时间、空闲状态与编码；联系软件配置，解释漏事件、反相、编码错和重复触发。能核对数字发送与接收两端的电气及逻辑兼容性。 |
| 7. 时序设计使记录与控制满足要求 | 各设备怎样对齐时间，控制响应是否足够及时？ | 区分触发、时钟、时间戳（数据附带的时间标记）与实际事件；理解延迟、抖动（延迟的逐次变化）和漂移（时钟偏差随时间累积）。比较共享时钟、共同事件对齐与软件时间同步；理解软件处理和数据缓冲对响应的影响。能从需求分配各环节允许的延迟，并通过测量验证。 |
| 8. 完整实例形成设计与排障方法 | 如何从需求独立完成系统方案，并证明其有效？ | 汇总需求、设备职责、接口选择、连接、软件配置、数据保存与验证；从信号源、传输、接收、软件记录和实际执行逐段定位异常。比较实验室与产品的具体取舍，形成可迁移的判断方法。 |

### 第一期内部结构（2026-09-13 修订）

实验问题 → 要测什么 → 对测量的要求 → 常用实现方式（仅测量手段类别） → 验收依据。

- 实验问题：要回答的问题是什么。
- 所需证据：什么样的观测或比较能支持或否定结论。
- 信息清单：为得到这些证据，需要测量和记录哪些信息（闭环需另记判定时刻）。
- 性能要求：每项信息要达到的要求，用现象的量书写；要求多严取决于未达到时哪条结论出错。
- 验收依据：哪个量、相对什么、允许误差多少、用什么测量证明；产出需求与验收清单。

输入链分生成段（只写要求，实现归第 5、6 期）与测量段。

闭环主例（Roux et al., 2017）只作例子，在讲到对应概念时引用一两个事实，不作为本期主线。

清单向后交接：谁完成各项 → 2；两端怎样连接 → 3；现象的量换算为采样参数 → 4；刺激指令 → 5；事件与判定 → 6；允许时间分配到各环节 → 7；逐条验收 → 8。

### 复核后的关键调整

- 第一期补充性能要求：明确需要的信息之后，还要问允许多少误差、光须多快亮起，以及失效会影响什么。需求只用现象的量书写，精度、带宽、延迟、抖动等设备概念在第 4、7 期定义。测量、控制、执行的职责划分归第二期。
- 第二期加入系统职责分配，明确从需求到接口之间的步骤。电脑、采集器、传感器和执行设备是可用组件，职责分配由任务决定。模拟输入输出和数字输入输出按需采用。
- 将电气基础提前到第三期，先解释连接成立的条件，再进入各类端口；后续每期复用这些基础处理具体接法。
- 时间要求在第一期提出，时钟和记录位置在第二期标明，各接口单元随需解释采样或事件识别时间，第七期汇总为整体时序设计与验证。
- 排障随原理分散讲解，第八期组织为统一方法。测试工具在首次需要时介绍，第八期比较其用途：万用表用于电压等基本电气量，示波器观察电压随时间的变化，逻辑分析仪观察数字状态与时序。

### 跨期教学方式与完整性要求

- 主例从第一期起即为闭环（测得的结果影响后续控制）：检测到特定神经活动即给光刺激，同时记录神经信号与行为视频。保持主例的连续性，同时说明每次新增的需求。
- 人体脑电与产品作为对应场景贯穿各期，第八期再集中对照集成程度、使用环境、可靠性与维护要求。涉及人体或动物的连接，明确设备的使用条件和隔离边界。
- 每期包含一个具体需求、必要原理、工程判断、连接示意、典型异常和验证依据。每个新概念先解释再使用；原理深度以能解释选择与故障为准。
- 覆盖软件与记录环节：端口配置、通道映射、输入输出模式、标度、事件保存和时间信息，分别归入对应接口或时序单元。
- 每期形成一份可复用的成果：①需求与验收清单；②系统信息图；③连接兼容性核对表；④模拟输入测量链；⑤模拟输出控制链；⑥数字事件收发图；⑦时序图与验证方案；⑧整合后的设计和排障指南。
- 第八期设置一个更换传感器或控制设备的迁移实例，用来检查读者能否重新判断方向、电气兼容、数据解释与时间要求。
- 具体器件内部物理按需要补充。型号特有的引脚、电压和操作步骤引用说明书，通用判断逻辑在系列内部解释完整。
- 具体厂商方案与数值在展开时查阅官方资料核实。大纲中的小鼠实例是教学设定。

### 第一期大纲：实验目的决定信息与性能需求（待确认）

本期要形成的能力：把一个实验问题转成有依据的信息清单与性能要求，说明每项记录的用途，以及什么程度的记录才足以回答问题。

递进关系：实验问题 → 所需证据 → 信息清单 → 性能要求 → 验收依据。设备与接口选择在后续展开。

1. **明确希望判断的变化。** 从“小鼠受到光刺激后，神经活动和行为怎样变化”出发，区分关注变化是否发生、变化幅度，还是刺激与响应的先后及间隔。明确观察对象、比较条件与观察时间范围；例如刺激前后、刺激与对照条件。本期简述比较依据的必要性，具体实验设计另行确定。
2. **把问题转成需要的证据。** 明确哪些观测支持预期判断：电信号中的变化、行为中的变化、实际刺激记录，以及它们的时间关系。区分直接测到的量与依据数据作出的解释。区分控制指令、实际执行与对象响应，避免用指令记录代替执行验证。
3. **列出必须收集的信息。** 将证据需求整理为神经活动、行为、刺激与时间信息，并补充理解记录所需的条件信息，例如记录位置、刺激参数、试次及条件标签。每项信息写清回答哪个问题，以及缺失后哪项判断无法完成。
4. **从判断尺度推导性能要求。** 根据关心的变化有多小、发生有多快、实验持续多久，提出幅值测量误差、时间分辨能力、跨记录对齐误差、连续记录时长与允许缺失等要求。区分事后分析与实时控制：实时任务另外规定从检测到执行的允许延迟。不预设统一参数，说明数值应由目标效应、已有证据或预实验支持。
5. **将要求写成可验证的清单。** 汇总“问题—所需信息—允许误差或遗漏—验证依据”，标记尚待查证的数值。回看每项要求是否足以支持最初判断，并明确哪些缺失会使实验无法解释。下一期据此分配设备职责与信息通路。

本期交付：一张需求表，字段为“需要作出的判断／所需信息／性能要求及依据／如何验证”。数值尚无依据时写“待确定”，说明需要的文献或预实验依据。

本期边界：讲清要求如何产生、如何判断充分性；具体器件、端口、接线与信号处理算法留给后续。必要术语随问题出现并解释，性能指标按幅值、时间、完整性分组呈现。
